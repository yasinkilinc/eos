## 0.1 What actually runs (the real architecture)

```
Claude Code session (the only executor of code/tests/edits; subagents = Claude Code Task tool)
 ├─ settings.json hooks (written by `ruflo init`, v3/@claude-flow/cli/src/init/settings-generator.ts:288-492)
 │    every event → `node .claude/helpers/hook-handler.cjs <cmd>` (new Node process per event)
 │      route         (UserPromptSubmit) → router.js keyword table (8 agents) + intelligence.cjs top-5 trigram/PageRank context
 │      pre-bash      (PreToolUse Bash)  → 4-string denylist, exit 1 (non-blocking in Claude Code)
 │      post-edit     (PostToolUse W/E)  → append .claude-flow/data/pending-insights.jsonl
 │      session-restore/-end, post-task (SubagentStop) → JSON graph rebuild, PageRank, confidence ±
 │      + detached `npx @claude-flow/cli hooks refresh-funnel|refresh-advisor` (promo/advisor, ADR-305/316)
 ├─ MCP server `ruflo mcp start` (stdio) → ~N tools in v3/@claude-flow/cli/src/mcp-tools/*.ts
 │      state = JSON files under .swarm/ .claude-flow/ + optional SQLite/AgentDB; recommendations returned as text
 │      model tier surfaced as a string: "[TASK_MODEL_RECOMMENDATION] Use model=\"haiku\"" (hooks-tools.ts:1620)
 └─ CLAUDE.md (69.6 KB in this repo; 7.5-11.3 KB generated) instructs the LLM to call MCP first, then Task tool,
    and to read the recommendation markers (CLAUDE.md:84-106). Nothing enforces it.

Separate runtimes that exist but are NOT the default path:
 - agent_execute → direct Anthropic/OpenRouter/Ollama HTTP (agent-execute-core.ts:607-615)
 - headless workers / daemon → `claude -p` subprocesses (services/headless-worker-executor.ts)
 - v3/@claude-flow/swarm, v3/@claude-flow/hooks, v3/@claude-flow/providers packages: library code the CLI does not import
```

The CLI's own `package.json` depends on `cli-core, codex, mcp, neural, plugin-agent-federation, security, shared, memory`
(v3/@claude-flow/cli/package.json) — **not** on `@claude-flow/swarm`, `@claude-flow/hooks`, `@claude-flow/providers`.
`@claude-flow/guidance` is shipped in the root tarball (package.json `files`) and lazily imported only by the
`guidance` CLI command (src/commands/guidance.ts:59-494) and the guidance MCP tools.
CLAUDE.md says it plainly: "Ruflo is the coordination ledger and policy decision point. Claude Code executes code …
A Ruflo coordination call records work; it does not perform the implementation." (CLAUDE.md:20-22) and
"Never use MCP tools alone for execution — Task tool agents do the actual work" (CLAUDE.md:88).

## 3. Agent routing (which agent type for a task)

Four independent agent routers exist; they do not share a model or a label set.

| Router | Where it runs | Algorithm | Verdict |
|---|---|---|---|
| **A. Prompt-hook keyword router** | every UserPromptSubmit via `hook-handler.cjs route` | first-match regex over 8 token lists → 8 agents; fixed confidence 0.6 (match) / 0.3 (default `coder`) | IMPL (the only router on the hot path) |
| **B. `hooks_route` MCP / `ruflo hooks route`** | when the LLM calls the tool | AgentDB SemanticRouter pre-route (duck-typed, optional) → 384-d "semantic" index over pattern keywords → keyword fallback | IMPL, but default embedder is a character hash |
| **C. Q-learning router** | `ruflo route` CLI + SONA optimizer only | tabular Q-learning over 64-d hashed keyword features, 8 routes, ε-greedy from ε=1.0 | IMPL, not on any hook path |
| **D. typesafe router** | `hooks_route` when `CLAUDE_FLOW_ROUTER_TYPESAFE=1` | `@ruvector/typesafe` classifier with abstain/lift/margin gate | OPT-IN |

**A — hot-path keyword router** (`.claude/helpers/router.cjs`, shipped as `v3/@claude-flow/cli/.claude/helpers/router.js`,
generated by `src/init/helpers-generator.ts:260-352`):
- `TASK_PATTERNS` (router.cjs:30-45): coder `implement|create|build|add|write code|refactor|debug`; tester `test|spec|coverage…`;
  reviewer `review|audit|check|validate|security`; researcher; architect; backend-dev; frontend-dev; devops.
- Single tokens get `\b…\b` (fix for #2257: "sync and review la**test** issues" → `tester`), phrases literal (router.cjs:54-64).
- `routeTask` returns the **first** matching entry, confidence constant 0.6, else `coder` @0.3 (router.cjs:72-91). No scoring,
  no tie-break, order-dependent ("add tests" → coder because the coder row is first).
- The header is honest: "NOT a learned model … confidence is a heuristic prior" (router.cjs:5-7).
- Output is a printed ASCII box injected into the prompt context (hook-handler.cjs:375-387). It does not select a model.
- ADR-389 exists only because installed copies of `router.js` were never refreshed (`init` skips existing files;
  `CRITICAL_HELPERS` omitted it) — the maintainer's own machine ran the substring router for months (v3/docs/adr/ADR-389-refresh-the-keyword-router-helper.md:18-26).

**B — `hooks_route`** (`src/mcp-tools/hooks-tools.ts:1156-1384`):
1. Optional AgentDB pre-route `bridgeRouteTask` (memory/memory-bridge.ts, "Phase 5"): duck-typed `registry.get('semanticRouter')`
   or `learningSystem.recommendAlgorithm`; wins if confidence > 0.5 (hooks-tools.ts:1178-1212).
2. Local route: 12 static `TASK_PATTERNS` (security/testing/api/performance/refactor/bugfix/feature/database/frontend/devops/swarm/memory,
   hooks-tools.ts:249-298) merged with learned patterns; **every keyword** is embedded separately and indexed
   (native `@ruvector/router` HNSW VectorDb M=16 ef=200/100, else pure-JS cosine) (hooks-tools.ts:364-447).
3. Eligibility: similarity > 0.4; learned patterns additionally need support ≥ 2 and reliability ≥ 0.75 (hooks-tools.ts:1315-1321).
4. Fallback `suggestAgentsForTask`: first `\b`-anchored keyword with hand-set confidences (test 0.95, security 0.92, auth 0.85…)
   (hooks-tools.ts:785-803, 826-839); then learned keyword overlap ≥ 2 → `min(0.6+0.05·overlap, 0.85)`; default
   `['coder','researcher','tester']` @0.7 (hooks-tools.ts:841-865).
5. "complexity" in the result is `includes('complex'|'architecture') || length>200 → high; 'simple'|'fix'||length<50 → low`
   (hooks-tools.ts:1338-1343); `estimatedDuration` strings and `successProbability = confidence` are derived constants.
- **Default embedder is a character hash**, not a sentence model: `generateSimpleEmbedding` sums `sin/cos(charCode·(i+1)…)`
  (ruvector/router-embedder.ts:74-97); `DEFAULT_ROUTER_EMBEDDER = 'hash'` (router-embedder.ts:28). ADR-390 admits it
  "measures spelling, not meaning" (router-embedder.ts:4-8). MiniLM is opt-in via `CLAUDE_FLOW_ROUTER_EMBEDDER=minilm`.
- Learned patterns (`services/learned-routing.ts:46-123`, #2839) are a sound discriminative-keyword learner:
  score = within-agent support × mean quality × `ln(1+A/df)` × discriminative share, filters support ≥ 2, quality ≥ 0.65,
  share ≥ 0.6, top-50 keywords per agent. Input = `.claude-flow/routing-outcomes.json` (cap 500) written by `hooks_post-task`
  only when the LLM passes `task` + `agent` (hooks-tools.ts:1784-1798).
- The tool **description** promises "a 3-tier routing recommendation … Returns the recommended model + `[CODEMOD_AVAILABLE]`"
  (hooks-tools.ts:1158) but the handler returns agent routing only; no model/tier field exists in `routeTaskLocal`'s result
  (hooks-tools.ts:1345-1383), and the typesafe wrapper only adds its own embedder name (ruvector/typesafe-router.ts:251-290).
  Plugins still grep its output for the obsolete `[AGENT_BOOSTER_AVAILABLE]` literal (plugins/ruflo-cost-tracker/skills/cost-booster-route/SKILL.md step 3).

**Measured accuracy (their own benchmark, ADR-391, 2026-09-23)** — 197 blind-labelled prompts, 113-prompt test split
(v3/docs/adr/ADR-391-router-benchmark-gate.md:86-118; receipt `v3/@claude-flow/cli/benchmarks/router/results/router-bench-2026-09-23.json`):

| Candidate | Top-1 acc | Macro-F1 | Wrong at ≥0.7 conf | p95 warm |
|---|---|---|---|---|
| A default (hash) | **25.7 %** | 0.178 | 29.2 % | 1.06 ms |
| B MiniLM | 36.3 % | 0.334 | 46.9 % | 6.21 ms |
| C typesafe-hash | 26.5 % | 0.199 | 26.6 % | 1.20 ms |
| D typesafe-ONNX | 29.2 % (raw pick 44.3 %) | 0.227 | 26.6 % | 8.35 ms |

No candidate was promoted (B failed a relative +5 % p95 latency rule on a ~1 ms baseline). The ADR also records that the
pattern table **cannot return `researcher`, `reviewer` or `none` as primary**, capping accuracy near 70 % before any
embedder question (ADR-391:106-110). This benchmark gate itself (frozen hashed corpus, dev/test split, AND-gate,
receipts committed "whatever the outcome") is one of the best-engineered artifacts in the repo.

**C — Q-learning router** (`ruvector/q-learning-router.ts`): 8 routes (`coder…documenter`, :162-171), 64-d features =
32 keyword-presence bits + length/word-count buckets + 8 extension bits + 8 hashed-bigram bins (:770-816), FNV-folded state key
(encoder v2 after #2239 found v1 silently dropped the keyword block, :110-135), ε-greedy with exponential decay from 1.0,
replay buffer, persisted to `.swarm/q-learning-model.json`. A contextual bandit in practice (single-step rewards).
Used only by `ruflo route` (commands/route.ts:53-61) and `memory/sona-optimizer.ts:284`. Cold start = uniformly random routes.

**Strengths:** honest in-code labelling of heuristics; word-boundary fix; learned-pattern math with support/reliability gates;
a real, pre-registered router benchmark with a published negative result.
**Weaknesses:** four routers, four label sets (8 hot-path agents vs 12 pattern groups vs 8 Q-routes vs ~60 agent files);
hot path is first-match keywords; "semantic" default is a char hash; confidences are constants that downstream code presents
as `successProbability`; learning only happens if the LLM remembers to call `hooks_post-task` with `agent` + `task`.
**EOS relevance:** copy the *benchmark discipline* (frozen labelled corpus + dev/test split + AND-gate + committed receipts,
include "abstain/none" labels) and the discriminative keyword learner; do not copy per-keyword hash "embeddings" or
multiple divergent label sets. Make the label set coverage-complete (ADR-391 finding 1) before tuning the scorer.

## 4. Model routing / effort selection (critical)

### 4.1 Inventory — three model routers, not one

| Router | Entry points | Decision | Verdict |
|---|---|---|---|
| **`ModelRouter`** (heuristic + Thompson bandit) | `hooks_model-route`, `hooks_model-outcome`, `hooks_model-verify`, `ruflo hooks model-route`, agent_spawn fallback | stochastic: complexity-scaled scores × Beta samples, then uncertainty escalation | IMPL |
| **`EnhancedModelRouter`** ("ADR-026 3-tier") | `hooks_pre-task` (hooks-tools.ts:1588-1625), `ruflo hooks pre-task` (commands/hooks.ts:2032-2058), `agent_spawn` (agent-tools.ts:208-244) | deterministic codemod tier-1 → ≥2 "tier-3" regexes → complexity thresholds 0.3/0.6 | IMPL |
| **Neural cost-optimal router** (ADR-148/149) | inside `ModelRouter.route` when `CLAUDE_FLOW_ROUTER_NEURAL=1` **and** an embedding is passed | `@metaharness/router` kNN/KRR (+ optional FastGRNN) → per-tier quality → Beta prior bump | OPT-IN (peer dep) |

The model decision is **never applied mechanically**. There is no PreToolUse hook on `Task`/`Agent` in the generated
settings (settings-generator.ts:294-344 registers only `Bash` and `Write|Edit|MultiEdit`), and no code in the CLI emits
`hookSpecificOutput.updatedInput` (the only `updatedInput` plumbing is in the un-imported `@claude-flow/hooks` bridge,
v3/@claude-flow/hooks/src/bridge/official-hooks-bridge.ts:224-226). The tier reaches the model as text —
`[TASK_MODEL_RECOMMENDATION] Use model="${model}"` (hooks-tools.ts:1620) or `[CODEMOD_AVAILABLE] …` (:1608) — and CLAUDE.md
tells the LLM to look for those markers before spawning Task agents (CLAUDE.md:103-106). `--mode moa` prints a
"MoA Execution Directive" asking the LLM to spawn N `model="haiku"` Task calls (commands/hooks.ts:874-981).
The only mechanical application is `agent_spawn` → `agent_execute`, which calls provider HTTP APIs directly with the routed
model (agent-execute-core.ts:607-615) — a separate runtime from Claude Code.

There is **no effort / reasoning-budget selection** anywhere (no `effort`, `budget_tokens`, `thinking` in v3/@claude-flow/**/*.ts);
routing is tier-only.

### 4.2 `ModelRouter` — exact features, weights, thresholds (`v3/@claude-flow/cli/src/ruvector/model-router.ts`)

Tier table (`MODEL_CAPABILITIES`, :137-167): haiku maxComplexity 0.4, cost ×0.04, speed ×3.0 · sonnet 0.7, ×0.2, ×1.5 ·
opus 1.0, ×1.0, ×1.0 · `inherit` 1.0. (`maxComplexity`/`speedMultiplier` are descriptive only; nothing reads them.)

Complexity score (`analyzeComplexity`, :836-871) — pure lexical arithmetic, no model:
```
score = clamp01( 0.20·lexical + 0.35·semanticDepth + 0.25·taskScope + 0.20·uncertainty )
lexical       = 0.4·min(1, words/50) + 0.6·min(1, (avgWordLen−3)/7)                          (:876-886)
semanticDepth = clamp01(0.3 + 0.30·#high + 0.15·#medium − 0.10·#low)  [substring includes()]   (:891-911)
                high  = architect design refactor optimize security audit complex analyze investigate
                        debug performance scale distributed concurrent algorithm system integration
                medium= implement feature add update modify fix test review validate check improve enhance extend
                low   = simple typo comment format rename move copy delete documentation readme config version bump (:172-186)
                (+ if an embedding is supplied: 0.7·base + 0.3·min(1, 10·variance(embedding)))
taskScope     = 0.4·[multi-file regex] + 0.3·[codegen regex] + min(0.3, words/100)              (:916-935)
uncertainty   = min(1, 0.2·#matches of /not sure|might|maybe|possibly|investigate|figure out|unclear|
                unknown|debug|strange|weird|issue|problem|error|bug/)                           (:940-949)
bucket        = low <0.4 | med <0.7 | high                                                        (:340-344)
```
Base scores (:954-966): `haiku = max(0, 1−2s)`, `sonnet = 1−2|s−0.5|`, `opus = min(1, 1.5s)`, `inherit = 0.1`.
Circuit breaker (:971-987): consecutive failures ≥ 5 → score ×0.1; else ×(1 − 0.5·failures/5). Process-local counters.

Selection (`selectModel`, :998-1102): Thompson sampling — `sampled_m = score_m × θ_m`, `θ_m ~ Beta(α_m, β_m)` of the task's
bucket (Marsaglia–Tsang gamma sampler, :401-445); argmax over haiku/sonnet/opus;
`confidence = best/(best+second+0.01)`; `uncertainty = max(0, 1 − (best−second) − 0.5·confidence)` (:1044-1048).

**The uncertainty gate (#2250)** (:1050-1099): if `uncertainty > maxUncertainty` (default **0.15**, env
`CLAUDE_FLOW_MAX_UNCERTAINTY`, :504-517) and pick ≠ opus → escalate one tier (haiku→sonnet, sonnet→opus) **unless**
(a) target posterior mean < selected mean − 0.10, or (b) selected arm has α+β ≥ 5 and mean ≥ 0.45, or (c) the neural prior's
top tier equals the pick. The code comment documents the bug: "`uncertainty` here is structurally ~0.6-0.7 for
low-complexity tasks … With `maxUncertainty = 0.15` the gate fires on ~every trivial route … The learned suppression is
computed and then discarded one line later." The fix only engages **after learning**; cold-start (Beta(1,1)) routers
still escalate. Measured (Appendix A, 4 000 draws each, cold start):

| Prompt | score | gate on (default) h/s/o | gate off h/s/o |
|---|---|---|---|
| fix typo in README | 0.117 | **24 / 57 / 19 %** | 80 / 14 / 5 % |
| bump version to 3.2.1 | 0.077 | 39 / 50 / 11 % | 91 / 6 / 3 % |
| add a unit test for the parser | 0.246 | 0 / 42 / **58 %** | 43 / 39 / 18 % |
| implement pagination for the orders endpoint | 0.317 | 0 / 18 / **82 %** | 15 / 55 / 30 % |
| design a distributed event-sourced architecture … security audit | 0.460 | 0 / 16 / 84 % | 0 / 61 / 39 % |

So on a fresh install a one-word typo fix goes to opus ~1 in 5 times and a small test to opus most of the time;
with the gate off the tier is still a coin flip weighted by complexity (opus 5 % on a typo). The score is also compressed:
even a keyword-dense architecture prompt scores 0.46 (bucket `med`); ≥ 0.7 needs a ~70-word prompt stuffed with
indicator words (0.925 in Appendix A), so the `high` bucket is rarely populated.

Learning (`recordOutcome`, :1158-1221): cost-weighted Bernoulli rewards (`BANDIT_REWARDS`, :321-326)
haiku success 1.0 · sonnet 0.7 (escalated 0.1) · opus 0.4 · failure 0; `α += r, β += 1−r` in the task's bucket
(bucket re-derived from the task text, :1170-1174); optional discounted TS `priorDecay` (default 1 = off, floor 0.05,
:1199-1213); persisted to `.swarm/model-router-state.json` (whole-file JSON rewrite after **every** route and outcome,
`autoSaveInterval: 1`, :520-521, :1358-1370; no locking between concurrent processes). After 10 haiku successes on one
low-bucket task the router picks haiku 100 % for it and 93 % for an unrelated low-bucket task (Appendix A) — learning is
per-bucket, i.e. it generalises across everything below score 0.4.

Outcome sources: `hooks_model-outcome` (LLM must call it, hooks-tools.ts:4979-5011); `hooks_model-verify` (records
success/escalated from the verifier, :5048-5098); `agent_execute` records **"success = the model returned a response
without an API error"** (agent-execute-core.ts:665-681). Combined with haiku's 1.0 vs opus's 0.4 reward, any HTTP-200 answer
from haiku is scored as the most valuable outcome — the reward is cost-biased and quality-blind.
Per-modelId shadow priors (`priorsById`, :347-356, :1238-1272) accumulate but "NOT consumed by selectModel()".
Dead config: `confidenceThreshold` 0.85 and `preferSpeed` are declared (:193-207, :516-523) but never read;
`hooks_model-route` accepts `preferSpeed`/`preferCost` and ignores them (hooks-tools.ts:4936-4960).

### 4.3 `EnhancedModelRouter` — the "3-tier" router actually used by pre-task/agent_spawn
(`v3/@claude-flow/cli/src/ruvector/enhanced-model-router.ts`)
1. **Tier 1 = deterministic codemod, not Agent Booster.** Regex intent detection over 6 intents with weights
   (var-to-const 1.0, remove-console 0.95, add-types 0.9, add-logging 0.85, async-await 0.8, add-error-handling 0.7; :109-187);
   +0.1 if the file exists; threshold 0.7; only `var-to-const | remove-console | add-logging` are deterministic
   (codemods/engine.ts:20-34). If a target file resolves, a dry-run `applyCodemod` must report a change (:395-418).
   Execution = TypeScript-compiler AST + text-range edits (codemods/engine.ts:1-15), via `hooks_codemod` (hooks-tools.ts:5114-5245;
   single file, list, or glob ≤ 2 000 files, path containment). `canUseAgentBooster` is marked
   "@deprecated Agent Booster never performed these transforms" (:745-748); CLAUDE.md:106 agrees.
2. **≥ 2 hits of 18 `TIER3_KEYWORDS` regexes → opus**, confidence `min(0.95, 0.7+0.1n)` (:206-236, :439-454).
   Regexes include `jwt|permission|authorization`, `encryption|ssl|tls`, `algorithm|optimization`, `concurrent` — so
   "add JWT permission check to the orders endpoint" → opus (Appendix A).
3. Optional "AST complexity" of the target file: lines/1000, indent, control-flow and function counts (:560-590; regex, not AST).
4. `baseRouter.route()` is called but **only its `complexity` is used** — the Thompson pick and the #2250 escalation are
   discarded; `final = complexity (avg with AST) + 0.25 if one tier-3 keyword` → `< 0.3 haiku`, `< 0.6 sonnet`, else opus
   (:472-553). Thresholds differ from `ModelRouter`'s buckets (0.4/0.7). Net effect: pre-task routing is deterministic and
   cheaper than `hooks_model-route` for the same text (typo → haiku 100 % vs 24 %).
5. Returned `estimatedLatencyMs/estimatedCost` are constants per tier (1 ms/$0, 500 ms/$0.0002, 2 000 ms/$0.003, 5 000 ms/$0.015).

### 4.4 Neural / provider path (ADR-148/149) — OPT-IN
`neural-router.ts:1-27`: gated on `CLAUDE_FLOW_ROUTER_NEURAL=1` + an embedding + `@metaharness/router` importable; backends
kNN (seed rows), KRR (bundled `assets/model-router/seed-router.krr*.json`, isotonic calibrator on by default), FastGRNN
(`seed-router.fastgrnn.safetensors` via `@ruvector/tiny-dancer`). Output is not a direct pick: per-tier max predicted
quality → ranked `[1.0, 0.5, 0.2]` → Beta bump `α+q·w, β+(1−q)·w`, `w = CLAUDE_FLOW_ROUTER_NEURAL_WEIGHT` (default 5)
(model-router.ts:628-678, :1015-1026). `hooks_model-route` calls `router.route(task)` **without an embedding**, so the neural
path can never fire there; `agent_spawn` computes a MiniLM embedding first (agent-tools.ts:214-219).
Provider: `CLAUDE_FLOW_ROUTER_PROVIDER` / `OPENROUTER_API_KEY` → OpenRouter slug per tier from
`assets/model-router/openrouter-alts.json` (haiku→`inclusionai/ling-2.6-flash`, sonnet→`openai/gpt-4.1`) (model-router.ts:108-123);
that file's own caveat: "sensible starters, not measured", and single-judge scores "mildly inflated by ~8-10 pp"
(openrouter-alts.json `_meta`). Seed corpus behind the "Pareto wins": 15 queries × 3 repeats.
Retry: on 429/5xx/timeout `nextCostOptimalAlternative`, budget `CLAUDE_FLOW_ROUTER_FALLBACK_MAX_RETRIES` (default 1)
(agent-execute-core.ts:617-661). Price table `ruvector/model-prices.ts:36-54` (blended = in + 3·out).
Observability is well done: every result carries `routedBy: heuristic|bandit-fallback|hybrid` and optional
`neuralBackend`, A/B sampling by FNV hash (`CLAUDE_FLOW_ROUTER_AB_SAMPLE_RATE`), DRACO-shaped trajectories
(`CLAUDE_FLOW_ROUTER_TRAJECTORY=1` → `.swarm/model-router-trajectories.jsonl`).

### 4.5 Post-generation verification & escalation (`ruvector/output-verifier.ts`) — IMPL, $0
`hooks_model-verify` runs cheap structural checks — empty, < 20 chars, refusal regexes in first 240 chars, odd code-fence
count or dangling operator at the tail, 5× repeated line, TypeScript `transpileModule` syntax errors / `JSON.parse` for
code/JSON (:209-293) — and returns `{confident, suggestedModel, escalate}` on the ladder haiku→sonnet→opus (:74-79),
recording success/escalated into the bandit. Explicitly "not a semantic-quality judge" (:23-26). Tested (output-verifier.test.ts).

### 4.6 Cost tracking
`plugins/ruflo-cost-tracker` parses Claude Code session JSONL under `~/.claude/projects/<encoded-cwd>/` for token usage,
prices it (`scripts/_prices.mjs`) and stores records via `npx @claude-flow/cli memory store` in namespace `cost-tracking`;
a Stop hook runs it (plugins/ruflo-cost-tracker/scripts/track.mjs:1-40, hooks/hooks.json). Its own baseline doc marks the
token-saving figures (−32 %, −15 %, 352×) as "Claimed upstream, not yet verified" and asserts only Tier-1's structural $0
(plugins/ruflo-cost-tracker/docs/benchmarks/0002-baseline.md "Token-spend optimization claims").
Router-side cost: `costMultiplier` per tier and `model-prices.ts`.

### 4.7 Tests & evidence for model routing
`__tests__/router-bandit.test.ts` (uniform priors, reward arithmetic, persistence, bucket isolation, v1→v2 migration,
convergence to haiku on a **synthetic oracle whose "optimal" tier is defined by the same 0.4/0.7 bands**, priorDecay);
`__tests__/issue-2250-2251-regression.test.ts` (with a pre-learned suppressed-opus prior opus < 20 %; the cold-start case
only asserts a valid model is returned, :77-85); `codemod-engine/-routing/-corpus.test.ts`; `output-verifier.test.ts`;
`neural-router.test.ts` (1 132 lines); `ruvector/enhanced-model-router-neural-fields.test.ts`.
No test or benchmark measures tier-choice accuracy against labelled tasks or cost/quality outcomes of real routing.
`benchmarks/results/prior-decay-receipt.json` is a synthetic bandit simulation.

### 4.8 Verdict and EOS relevance
Real: the heuristic, bandit, bucketed priors, codemod tier, verifier, neural opt-in, provider hints, observability.
Weak: the heuristic is keyword-substring arithmetic with a compressed range; Thompson sampling makes the tier
non-deterministic for identical input; the cold-start uncertainty gate still over-escalates; two routers give different
answers for the same prompt; reward = API success; decisions are advisory text the LLM may ignore; no effort dimension.

For EOS (deterministic classify → score → tier → advise, no LLM, SQLite):
- **Keep deterministic selection**; if outcome learning is added, use it to *adjust thresholds/tiers per task class
  offline* (or as a tie-breaker), not per-call Thompson draws — reproducibility matters more for an advisor than exploration.
- **Never gate on a statistic whose scale you have not measured** (#2250): derive any "uncertainty/margin" gate from the
  empirical distribution of your own scores and add a regression test on the *cold-start* distribution, not only on a
  pre-learned state.
- **Reward must be task outcome, not API success**; and do not hard-code cheap-tier bonuses (haiku 1.0 / opus 0.4) that
  make any non-error cheap answer look optimal. EOS's run outcomes (`eos run finish --outcome`) are the right signal.
- **Bucket by task class, not by score band**: Ruflo's per-bucket priors generalise one typo success to all low-score tasks.
- **Adopt**: the Tier-0 idea as "deterministic transform available" advice (EOS already knows codemod-able ops per repo:
  e.g. config-id generation, changeset refs); the post-generation cheap verifier ladder (structural checks → suggest
  next tier); `routedBy`-style provenance on every decision; the A/B sampled-by-hash shadow evaluation; a frozen,
  hashed, blind-labelled router corpus with an AND-gate (ADR-391).
- **Enforcement option Ruflo lacks**: a PreToolUse hook on `Task`/`Agent` can return `hookSpecificOutput.updatedInput`
  with a `model` field — deterministic application instead of CLAUDE.md persuasion. Ruflo never does this.
- **Add what Ruflo lacks**: effort tier (EOS already routes `sonnet/medium`, `haiku/low`, `sonnet/high`).

## 6. Skills

**Format.** Standard Claude Code Agent Skills: `<dir>/SKILL.md` with YAML frontmatter `name`, `description`, optional
`argument-hint`, `allowed-tools` (e.g. plugins/ruflo-cost-tracker/skills/cost-booster-route/SKILL.md:1-6). No custom schema,
no manifest-level triggers, no code-side parser in the CLI (the only `SKILL.md` readers are the Codex generator/validator,
v3/@claude-flow/codex/src/generators/skill-md.ts, codex/src/validators/index.ts, and `init`/`doctor` file copies).

**Inventory.** 361 `SKILL.md` files: 39 in `.claude/skills/` (the set `init` copies; 605 KB total, up to 31 KB each —
hooks-automation 31 KB, github-project-management 29 KB), 33 in the CLI package, 135 in `.agents/skills/` (Codex mirror),
146 across 40+ `plugins/*/skills/` (409 KB total, ≤ 8 KB each — ADR-098's "lean agent prompt" rule, reference data in
`REFERENCE.md`). `skills.sh.json` is only a grouping catalogue for the third-party skills.sh directory.

**Discovery / selection / progressive disclosure.** Entirely Claude Code-native: the harness lists name + description,
loads the body on invocation. Ruflo's only lever is `"skillListingBudgetFraction": 0.06` in its own settings.json
(.claude/settings.json:3). `init` copies skill groups by flag (`SKILLS_MAP` core/agentdb/github/flowNexus/v3/browser/dualMode,
src/init/executor.ts:39-84, :1119-1165). The `.claude/skills` bodies are monolithic (no `references/` split) — the opposite
of progressive disclosure; the plugin skills are closer to it (short SKILL.md + REFERENCE.md).

**"Skill routing".** None at runtime. The capability brain (`src/mcp-tools/capability-brain.ts`, ADR-329) maps 20+
domains → `prefixes`, `taskSignals`, `commands`, `skills`, `agents`, maturity/authority/risk flags, loop phases,
`useWhen`, `verifyBeforeUse` (:47-76, :243-613); `recommendCapabilities` scores domains by **count of substring hits of
`taskSignals`**, top 6, fallback to guidance/tasks domains (:814-860). It is data-only and advisory, and it distinguishes
catalogued / registered / configured / reachable / healthy / authorized as separate facts (:774-781, health defaults
`'unknown'`, :759-765) — a genuinely good truth model.

**Drift.** Several skills describe behaviour the code no longer has (cost-booster-route greps `[AGENT_BOOSTER_AVAILABLE]`
from `hooks_route`, which emits neither that marker nor a model; `.claude/skills/sparc-methodology` advertises "17 specialized modes").

**EOS relevance.** EOS's procedures-as-notes delivered by the prompt hook are already a better progressive-disclosure design
than 30 KB SKILL.md files. Worth taking: the capability-brain *schema* (domain → tools/skills/agents, risk flags,
`verifyBeforeUse`, and the 6-state truth model) as the data model for "which EOS wrapper/procedure applies"; the ≤ 5-8 KB
skill budget with reference files; a CI check that every marker/literal a skill greps for is still emitted by code.

### 7.2 What each default hook does (shipped `v3/@claude-flow/cli/.claude/helpers/hook-handler.cjs`, identical to `.claude/helpers/hook-handler.cjs`)
- Every event = new Node process; stdin JSON with 500 ms read timeout; global 5 s kill; `intelligence.*` wrapped in a 3 s race
  that cannot interrupt the synchronous fs work it guards (hook-handler.cjs:240-264, :272-320).
- `route` (UserPromptSubmit): prints `intelligence.getContext(prompt)` then the keyword-router box (:367-391); may print a
  sponsored-capacity nudge `[COGNITUM] Hit your Claude usage limit? … run: ruflo proxy sponsor-enable --yes` into the model
  context when `~/.ruflo/rate-limit-status.json` is flagged and no consent receipt exists (:392-441).
- `pre-bash`: lower-cased substring check for 4 strings (`rm -rf /`, `format c:`, `del /s /q c:\`, fork bomb), then
  `process.exit(1)` (:444-459). In Claude Code only exit code **2** (or a JSON deny) blocks a PreToolUse call; exit 1 is a
  non-blocking error, so this "BLOCKED" path does not stop the command.
- `post-edit`: dedup by event id (sha256 marker file in tmpdir, :289-312), `session.metric('edits')`,
  `intelligence.recordEdit(file, success)` → append to `.claude-flow/data/pending-insights.jsonl` (capped ~512 KB/2 000 lines);
  failure detection from `tool_response` (:347-364, :461-475) — ADR-174 negative examples.
- `session-restore`: session file, `intelligence.init()` (dedupe store by id and content fingerprint, build graph, PageRank,
  write `ranked-context.json`), first-run auto-enable of "spinner verbs", detached `hooks refresh-funnel` and
  `hooks refresh-advisor` (the latter may run a consent-gated `claude -p` call once per 24 h, commands/hooks.ts:5595-5632).
- `session-end`: `intelligence.consolidate()` — files edited ≥ 3 times become "insight" entries, −0.005/day confidence decay
  for never-accessed nodes older than 24 h, rebuild edges, PageRank (v3/@claude-flow/cli/.claude/helpers/intelligence.cjs:731-897).
- `post-task` (SubagentStop): `intelligence.feedback(!toolFailed)` → ±0.05/−0.02 on the last matched patterns (:691-697).
- `pre-edit`, `post-bash`, `compact-manual`, `compact-auto`, `status`, `notify`: **no handler** in the shipped hook-handler →
  prints `[OK] Hook: <cmd>` (:580-583). (The generator fallback `generateHookHandler` prints static "54 agents / GOLDEN RULE"
  text for compact-*, helpers-generator.ts:718-735.)

### 7.3 The "hooks intelligence" layer
Hot path (installs): `intelligence.cjs` (1 169 lines, pure CJS, JSON files under `.claude-flow/data/`):
- Graph: nodes = memory entries (from `auto-memory-store.json`, bootstrapped from `MEMORY.md` files incl.
  `~/.claude/projects`), edges = temporal (same source file, w 0.5) + similarity (trigram Jaccard > 0.3 within a category,
  skipped above 100 000 comparisons) (:290-370); PageRank d=0.85, 30 iters, skipped above 5 000 nodes (:238-286, :540-548).
- Ranking at session start: `0.6·pageRank + 0.4·confidence` (:578-582). Retrieval at prompt time:
  `score = 0.6·Jaccard(trigrams(prompt), trigrams(entry)) + 0.4·pageRank`, threshold 0.05, **top-5**, each printed as ≤ 80 chars
  (:602-657). Implicit feedback: entries shown last prompt but not this one get +0.03 ("user continued working"); explicit via
  SubagentStop ±.
- This is simple, bounded and real. It is **not** SONA/LoRA/EWC; those live behind the MCP tools (`hooks_intelligence*`,
  `hooks_pretrain`, `neural_*`) and `memory/intelligence.ts` — covered by the memory/learning audit.
MCP side: 41 `hooks_*` tools (hooks-tools.ts:911-5434). Mixed quality: `hooks_codemod`, `hooks_model-*`, `hooks_route`,
`hooks_post-task` do real work; `hooks_pre-edit` returns canned content (`fileExists: true` hard-coded, `relatedFiles: []`,
`{pattern: "<ext> file editing", confidence: 0.85}`) (:922-948). 36 of the 41 `hooks_*` descriptions end with the same
258-character suffix ("Use when native Bash hooks (via Claude Code's settings.json) are wrong because you need Ruflo-side
state …"), and ~240 "Use when native … is wrong because …" clauses exist across `src/mcp-tools/*.ts` (ADR-112
discoverability) — paid for in every session's tool listing.
The `@claude-flow/hooks` package (typed `HookEvent` enum of 20 events, priorities 1000/100/50/10/1, registry, executor,
daemons, ReasoningBank guidance provider emitting proper `hookSpecificOutput.permissionDecision`) is not imported by the CLI —
library/DEAD for installs. Orphan helpers in `.claude/helpers/` (`context-persistence-hook.mjs` 2 001 lines "infinite
context" SQLite transcript archive; `patch-aggressive-prune.mjs`, which patches Claude Code's minified `cli.js`;
`guidance-hook.sh` calling `npx agentic-flow@alpha`) are referenced by no settings generator (no match in src/ or plugins/).

### 7.4 Latency claims vs code
Code comments give budgets (init < 200 ms, getContext < 15 ms, recordEdit < 2 ms, consolidate < 500 ms; intelligence.cjs:463,
:599, :660, :728) and the router logs "native VectorDb (HNSW, 16k+ routes/s)" / "pure JS (cosine, 47k routes/s)"
(hooks-tools.ts:409, :440); none of these are measured in CI. Every hook still pays a Node cold start; ruflo-core
plugin hooks pay a full CLI spawn. The CLI help hard-codes '84.8% SWE-Bench solve rate', '32.3% token reduction',
'2.8-4.4x speed improvement' (commands/hooks.ts:5733-5741).

### 7.5 EOS relevance
Transfer: the hook *catalogue shape* (prompt-submit = advise+context, post-edit = cheap append-only event log, session-end =
consolidate, subagent-stop = outcome feedback); event dedup by `tool_use_id`; failure capture from `tool_response`;
"always exit 0 except deliberate block"; bounded O(n²) guards; hash-fingerprint cache invalidation (#2920).
Avoid: blocking attempts via exit 1 (use exit 2 / JSON `permissionDecision`), per-event CLI spawns, promotional or
network side effects in hooks, handlers registered for events that have no implementation, and static filler text in
PreCompact. EOS's `wrapper_guard.py` (exit-2 refusal with a concrete alternative) is already the correct pattern.

## 10. Context assembly / token efficiency

What actually shapes the agent's context in a default install:
1. **CLAUDE.md** — generated templates are 174-278 lines / 7.5-11.3 KB (~1.9-2.8 k tokens) (measured, Appendix A; the
   generator's own labels say "~80 / ~140 / ~220 lines", src/init/claudemd-generator.ts:437-439); this repo's own CLAUDE.md
   is 69.6 KB (~17 k tokens) plus a 24.6 KB AGENTS.md.
2. **UserPromptSubmit output** — ≤ 5 memory lines of ≤ 80 chars + the router box (≈ 10 lines); no token budget parameter,
   no dedup against what is already in context (intelligence.cjs:602-657).
3. **MCP tool listing** — every registered tool's name/description/schema (see §8 for the count); the repeated 250-char
   hooks suffix is pure overhead.
4. **Skill listing** — capped by Claude Code (`skillListingBudgetFraction: 0.06`).

Mechanisms that exist but are not wired by default:
- `integration/src/token-optimizer.ts` — ReasoningBank compact context via optional `agentic-flow`; after #3289 it reports
  `tokensSaved: null` unless the caller supplies the size of the context it replaced (:120-192). The CLI's inline copy
  (`ruflo hooks token-optimize`) still computes "saved" as `query tokens − compact tokens`, the exact bug #3289 fixed in
  the library (commands/hooks.ts:4963-4969), and prints a hard-coded "Anti-Drift Swarm Config … Success Rate 95%" (:4943-4957).
- `cli/src/swarm/message-compressor.ts` — deterministic extractive compressor: preserve code fences/paths/URLs/tool
  directives, keep top TF-IDF sentences under `budgetTokens` (:1-40); "advisory tool + library … No auto-wire".
- `context-persistence-hook.mjs` (ADR-051) — SQLite transcript archive + "context autopilot" (3.5 chars/token, warn 70 %,
  prune 85 %, restore budget 4 000 tokens) — not registered by any generator.
- Guidance shard retrieval — see §9.
Claimed numbers: −32 % (ReasoningBank), −15 % (Agent Booster), −10 % (cache), −20 % (batch), 352×: the repo's own
cost-tracker plugin lists them as "Claimed upstream, not yet verified" (plugins/ruflo-cost-tracker/docs/benchmarks/0002-baseline.md).
No benchmark in the repo measures end-to-end token use against a baseline.

**EOS relevance:** EOS already measures median tokens per call (e.g. brief ≈ 287 tokens) — that is more than Ruflo does.
Transferable: the extractive compressor's "never compress load-bearing spans" rule; `null` instead of `0` for unmeasured
savings (#3289); top-k with a score floor for prompt-time recall. Avoid: large always-loaded instruction files and
duplicated tool-description boilerplate.
