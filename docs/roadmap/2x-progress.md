### Decided without asking

- N1: a synonym group's weight counts the notes using any member (planned: the rarest member's). The rarest spelling is often one no note uses, which would make the concept look rare and outweigh the query's real words.
- N1: groups are never merged; a word named in two groups stays in the first. Merging would let one careless entry join two meanings.
- N2: no `valid_from` field; `created` already says when a note starts to hold, and a second date could disagree with it.
- N2: a `valid_until` in the past is refused on add (the note would never be offered); an unparseable one on disk never hides a note.
- N2: the MCP `add_note` records provenance `agent` without a name -- the server does not know which agent calls it.
- Usage: the status line never ran in the VSCode session (no trace file after several turns), so the 50% rule cannot be read here; reported to the user, work continues until they give a reading.
- N3: `brief.py` and `inject.py` keep `CHARS_PER_TOKEN` as a re-export of `budget.CHARS_PER_TOKEN` instead of rewriting every importer to `core.context.budget` directly -- existing callers and tests (`brief.CHARS_PER_TOKEN`, `inject.CHARS_PER_TOKEN`) keep working unchanged, and there is still exactly one number to change. `context_cost.py` and `bench.py` import the name directly since nothing external depends on their own copy.
- N3: two telemetry tests pinned the old chars/4 estimate as a literal (`entry["chars"] // 4`, a hardcoded median of 2 from 4/8/400 chars); rewritten to call `budget.tokens(...)` and to the ratio's real median (3) rather than leaving them red or hand-picking chars that happen to still divide by 4.
- N4: the fold key is `(kind, tool, target, ref, exit_code, ms, status, agent)` -- exactly what the display line prints, `ord` and `at` excluded on purpose (they are what the marker replaces). A folded line prints its first `ord` and the first..last `at` range, not an `ord` range: nothing downstream reads an ordinal range and the run's own event count already answers "how many".
- N5: "used" prefers the session's `subagent_models` tally over `models` when both exist, because a routed decision is applied to a subagent call's own `model` field (`core.hooks._route_subagent`) -- the main session's model is the harness's or the user's choice, not this decision's. Compared by model id with any `[...]` context-window suffix stripped, so `model[1m]` counts as `model`. When a session ran more than one model, only the one with the most messages is compared -- the same one-value-per-session limit `advised_vs_used` already had; a per-message join is not possible from `routing-usage.jsonl`, which folds a whole session.
- N6: a scope entry covers a changed ref by exact match, as a directory prefix (`src/pkg` covers `src/pkg/x.py`), or as an `fnmatch` glob -- the three shapes procedure scopes are already written in (`note add --scope`), not `_scope_anchor`'s parent-link resolution (built for hashing a note's own scope files, not for matching arbitrary changed paths). The warning prints to stdout, matching the existing `claimed:` lines in the same command, not stderr.
- N8: all three of today's callers of `notes.procedures()` (`eos procedure list`, `executions.audit_procedures`, `consolidate._silent_steps`) pass `include_expired=True` -- the spec's parenthetical named "audit/lint/consolidate listing" but did not say whether the plain `procedure list` browsing command was one of them; the conservative reading (an existing command's output must not change) covers `list` too, so the new filtered default currently has no caller and is there for `best_procedure`-shaped matching to opt into by leaving the flag off.
- N8: `run start --procedure`'s expiry refusal matches only an exact slug (`expired_procedure`, mirroring `replacing_procedure`), not `find_procedure`'s prefix/title fallback -- a procedure slug that names nothing yet is not this refusal's problem, same as the existing replaced-procedure check.
- N9: a run's own commit range (`commit_start..commit_end`, what `run show` already prints) is what gets diffed, not the individual commits the run itself made -- on a shared repository this range can include another session's commits made in between, which inflates `touched` with files the run never went near. Named as a real limitation of the measurement rather than papered over: attributing files to the run that made them (not merely bracketed them) needs each `changed` event's own commit, which the ledger does not record.
- N9: `commit_start == commit_end` (no commit made during the run) is "unmeasurable", not "0 touched, 0 captured" -- a run that never committed is a run this measurement has nothing to say about, and a confident 0 would misreport that as a perfectly-captured empty change.
- N10: `--evidence` is refused by kind name at `note add` (mirroring how `defect`'s `cause`/`solution`/`metric` are required by kind), not by a generic "unknown field" -- the message says which kind actually owns it.
- N10: `amend_note` was given the same treatment as `execution`'s -- carried through untouched on every rewrite -- because leaving it out would make the very next `--body`/`--reaffirm` on a lesson silently drop its evidence, which is a worse regression than not having the field at all.
- N11: a Bash git call's `changed` events come from diffing the session's *last-seen* HEAD, not the run's `commit_start` -- the first mutating git call of a session only records today's HEAD as the baseline and diffs nothing, since there is no earlier HEAD to compare it to and loading the whole ledger for `commit_start` on every Bash call to price in one call's worth of files was not worth the read.
- N11: `BASH_CHANGED_LIMIT=200` -- a subtree squash can land hundreds of files in one Bash call; one `changed` event per file past that would flood the ledger for a single command with no proportionate benefit, since `touched_files` already sees the true count independent of how many `changed` events exist for it.
- N11: `_foreign_files` only drops a file when *every* commit naming it is foreign -- a file the run's own commit also touches is always kept, so the exclusion can only shrink `touched` (more conservative), never inflate `captured`'s share by shrinking the denominator under real work, and never overstate capture.
- N11: the subtree-squash prefix is read back out of the squash commit's own `Squashed '<prefix>' changes from ...` message rather than a config value -- general across any subtree mount (this host's `tools/eos` included) instead of one more thing to keep in sync with `.eos/config.toml`.
- N11: no version bump or release commit -- N1 through N10 (every other N-step) did not release either; only the RVa/RVb/RVc review steps have, and N11 is not a review.
